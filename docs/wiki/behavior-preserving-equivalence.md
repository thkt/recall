# 振る舞いを変えない整理と最適化は、変更前との一致を示す

## 内容

振る舞いを変えないと主張する整理・最適化・ビルド変更では、変更前のコードで通る固定テストを先に足すか、main と出力を全件比較して一致を示す。テストが通ったことだけを根拠にしない。

## 定型手順

1. 変更前のコードに対して、振る舞いを固定するテストを先に足して通ることを確かめる
2. 入力の組み合わせを列挙できる場合は、main と変更後の出力を全件比較する
3. CLI の help などの出力はバイト単位で比べる
4. 非決定性を疑う比較では、変更前同士（A/A）の一致を先に確かめてから変更前後（A/B）を比べる
5. テスト件数が変更前と同じことを PR 本文に書く

## 参照コード

- `src/native/real_tests.rs` の `real_model_bit_dump_for_build_parity`（トークン列と埋め込みのビット列を書き出して、ビルド間で比べる）
- `src/compat.rs` の `assert_filter_symmetric`（フィルターありとなしの結果を比べる共通 helper）
